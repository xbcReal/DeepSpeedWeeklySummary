重要特性 (Features)

#8189 Enable ZeRO-3 linear wrapper for existing models Feature
Author: tohtana (Masahiro Tanaka) | Merged: 2026-07-31
以往只有在 deepspeed.zero.Init() 上下文中构建的模型才会安装 ZeRO-3 Linear wrapper。此 PR 让通过 deepspeed.initialize(model=...) 传入已构建模型、并开启 memory_efficient_linear=true 的路径也能激活该 wrapper，避免标准 Linear 在 backward 完成前一直保留 gather 后的权重存储，显著降低显存占用。
#8184 Add managed_gradient_accumulation for ZeRO stage 0/1 Feature
Author: sfc-gh-truwase (Olatunji Ruwase) | Merged: 2026-08-02 | Part fix #8183
引入「非托管梯度累积」能力：当 managed_gradient_accumulation=false 时关闭内部 micro-step 计数，把每次 engine.step() 都当作累积边界（本地累积梯度后再 reduce 并执行优化器更新），让 HTTP/RPC 驱动的 RL 后端（如 Tinker 协议）可以自己掌控优化器步边界。ZeRO-0/1 先落地，Stage 2/3 与流水线暂不支持。对应 Issue #8183。
#8182 Add keyword argument support to activation checkpointing Feature
Author: zupengwang | Merged: 2026-08-02
让 deepspeed.checkpointing.checkpoint 对齐 torch.utils.checkpoint.checkpoint，支持传入关键字参数。Tensor 类型的 kwargs 会被展平进入输入以便 autograd 正确追踪并返回梯度，非 Tensor 值则保留用于前向/重计算重建，并补充了文档与回归测试。
#8146 [AutoTP] Enable HF colwise_gather_output to support lm_head replace Feature
Author: jinyouzhi | Merged: 2026-07-29
在 AutoTP 中启用 HuggingFace tp_plan 的 colwise_gather_output，为未 tied 的 lm_head 支持词表并行（vocab parallelism）。属于 Roadmap「集成 Liger Kernel / LM head 分片」方向的基础能力。当前仅支持未 tied 的 lm_head，非均匀 TP 暂未覆盖。
#8187 [AutoTP] Preserve universal checkpoint metadata for HuggingFace tp_plan Feature
Author: jinyouzhi | Merged: 2026-07-30
补齐 HuggingFace tp_plan 转换路径的 universal checkpoint 元数据：此前该路径替换模块后直接返回，未保留 ds_to_universal 所需的元数据（与 custom-config、heuristic AutoTP 路径不一致）。新增对 colwise / rowwise / 复制型 row-parallel bias / colwise_gather_output 的测试覆盖。
#8168 [AutoTP] Fix ZeRO-3 checkpoint consolidation to gather across TP and DP Feature
Author: delock | Merged: 2026-08-02
修复 AutoTP + ZeRO-3 静默生成不完整 checkpoint 的问题（上周处于 review，本周合入）：此前导出仅处理 ZeRO 数据并行维度、丢弃张量并行分片。改为在 ds_to_universal.py 与 engine.py 中跨 TP 和 DP 一并 gather，并移除了 AutoTP+ZeRO-3 训练的整体阻断。是 #8167 的后续 checkpoint 支持工作。

Bug 修复 (Bug Fixes)

#8195 MoE dispatch: fix silent Tutel + TP corruption, speed up native and Tutel paths Bugfix Perf
Author: jinyouzhi | Merged: 2026-08-02 | Follow-up #8174
对 deepspeed/moe/sharded_moe.py 的三处独立改动：(1) 修复 Tutel + 张量并行下 dispatch 缓冲区未按 capacity 分片导致的静默数据损坏；(2) 加速 k>2 的 Tutel 路由提取，用 gather 取代对每个 route 重建稠密 one-hot mask，并把 capacity 一次性解析避免逐次 device→host 同步；(3) 优化 native 路径。路由输出保持 bit-identical。属正确性 + 性能双重改进，值得重点关注。
#8202 Preserve tensor learning rates across scheduler updates Bugfix
Author: n33levo | Merged: 2026-08-02 | Follow-up #7633
修复 tensor 学习率支持在每次调度器更新时都会「替换」优化器 LR tensor 的问题：update_lr() 原先构造新的 tensor([lr])，改变了张量身份/形状/dtype，并使调用方持有的引用指向失效值。改为就地填充优化器已有的 LR tensor，与 PyTorch 调度器行为一致。是 #7633 tensor LR 支持的后续修复。
#8155 Clamp capacity to num_tokens in MoE gating drop branches (complete #5353) Bugfix
Author: ebarkhordar | Merged: 2026-08-02
修复 MoE gating 在 capacity_factor * k > num_experts 时 capacity > num_tokens 导致 torch.topk(..., dim=0) 抛出 "selected index k out of range" 的问题。#5353 只在 top1gating 的 no-drop 分支加了 capacity = min(capacity, num_tokens) 守卫，本 PR 补齐了两个真正会喂给 topk 的 drop 分支。
#8179 Make the OneCycle stair counts actually change the schedule Bugfix

#8196 Release GIL in blocking AIO bindings Bugfix

#8089 Warn when zero.Init silently falls back to a single rank (#8084) Bugfix
